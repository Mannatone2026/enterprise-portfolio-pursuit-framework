# Type System Reference

Absorbed from the dropped `postgres-syntax-types-domains` skill per decision D-010. PostgreSQL's type system is the richest of any open-source RDBMS and the right choice of type prevents a class of subtle bugs.

## Numeric Types

| Type | Storage | Range | Use case |
|---|---|---|---|
| `smallint` (`int2`) | 2 bytes | -32768 .. 32767 | Bounded counters where range is known |
| `integer` (`int4`) | 4 bytes | -2^31 .. 2^31-1 | Default integer choice |
| `bigint` (`int8`) | 8 bytes | -2^63 .. 2^63-1 | IDs, anything that might exceed 2 billion |
| `decimal` / `numeric(p, s)` | variable | up to 131072 digits before, 16383 after decimal | Currency, exact math : NEVER use float for money |
| `real` (`float4`) | 4 bytes | ~6 decimal digits precision | Scientific values where exact precision is not required |
| `double precision` (`float8`) | 8 bytes | ~15 decimal digits precision | Scientific values, geometry |
| `smallserial` / `serial` / `bigserial` | 2 / 4 / 8 bytes | autoincrement | LEGACY : use IDENTITY columns instead since v10 |

PREFER `int GENERATED ALWAYS AS IDENTITY` over `serial`. The IDENTITY form is the SQL-standard equivalent and avoids the `serial` privilege foot-gun (where any user with INSERT on the table can advance the sequence).

```sql
-- LEGACY (avoid)
CREATE TABLE t1 (id serial PRIMARY KEY);

-- PREFERRED (v10+)
CREATE TABLE t2 (id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY);

-- ALSO VALID : application can override
CREATE TABLE t3 (id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY);
```

Source : postgresql.org/docs/17/datatype-numeric.html, postgresql.org/docs/17/sql-createtable.html.

## Text Types

| Type | Storage | Use case |
|---|---|---|
| `text` | variable | DEFAULT choice for any string |
| `varchar(n)` | variable, max n chars | Only when an enforced length limit is a business requirement |
| `char(n)` | fixed-padded to n | LEGACY : pads with spaces, rarely the right choice |
| `citext` | variable | Case-insensitive comparison (contrib extension) : prefer a functional index on `lower(col)` instead |
| `name` | 64 bytes | Internal identifiers only ; not for user data |

`text` and `varchar` have identical performance when no length is specified. Pick `text` unless a length cap is a business invariant. `char(n)` pads with spaces and almost always surprises ; avoid it.

```sql
CREATE TABLE products (
  id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sku text NOT NULL UNIQUE,            -- no arbitrary length cap
  description text                      -- not varchar(unlimited)
);
```

Source : postgresql.org/docs/17/datatype-character.html.

## Date/Time Types

| Type | Storage | Resolution | Range |
|---|---|---|---|
| `timestamp` (without tz) | 8 bytes | 1 microsecond | 4713 BC to 294276 AD |
| `timestamptz` (with tz) | 8 bytes | 1 microsecond | 4713 BC to 294276 AD |
| `date` | 4 bytes | 1 day | 4713 BC to 5874897 AD |
| `time` (without tz) | 8 bytes | 1 microsecond | 24-hour clock |
| `time with time zone` | 12 bytes | rarely useful, AVOID | -- |
| `interval` | 16 bytes | 1 microsecond | months / days / microseconds |

ALWAYS use `timestamptz` for any event time. `timestamptz` stores UTC and converts to the session's `TimeZone` setting on display ; `timestamp` stores wall-clock-with-no-zone and silently produces wrong results when sessions are in different time zones.

```sql
-- WRONG : wall-clock without zone
CREATE TABLE events (occurred_at timestamp NOT NULL);

-- RIGHT : UTC-anchored, zone-displayed
CREATE TABLE events (occurred_at timestamptz NOT NULL DEFAULT now());
```

Source : postgresql.org/docs/17/datatype-datetime.html.

## Boolean

| Type | Storage | Values |
|---|---|---|
| `boolean` | 1 byte | `TRUE` / `FALSE` / `NULL` |

NULL is a third state. `WHERE bool_col` matches only `TRUE` ; `WHERE bool_col IS FALSE` excludes NULL ; `WHERE bool_col IS NOT TRUE` includes NULL.

Source : postgresql.org/docs/17/datatype-boolean.html.

## UUID

| Type | Storage | Generator |
|---|---|---|
| `uuid` | 16 bytes | `gen_random_uuid()` (pgcrypto, v13+ in core) or `uuidv7()` (v18+) |

`gen_random_uuid()` produces UUIDv4 ; random distribution is bad for B-tree locality on `INSERT`. UUIDv7 (time-ordered) is much friendlier but requires v18+ or a custom function.

```sql
CREATE TABLE sessions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  ...
);
```

Source : postgresql.org/docs/17/datatype-uuid.html.

## Network Address Types

| Type | Storage | Use case |
|---|---|---|
| `inet` | 7 or 19 bytes | IPv4 / IPv6 host address, optional /netmask |
| `cidr` | 7 or 19 bytes | IPv4 / IPv6 network ; rejects host bits set in network portion |
| `macaddr` | 6 bytes | MAC address (48-bit) |
| `macaddr8` | 8 bytes | EUI-64 MAC address |

`inet` supports network operators : `<<` (subnet of), `<<=` (subnet of or equal), `>>`, `>>=`, `&&` (overlaps), `host()`, `network()`, `broadcast()`, `family()`, `masklen()`. Index with B-tree (range) or GiST (`<<` / `>>` / `&&`).

```sql
CREATE TABLE access_log (
  client inet NOT NULL,
  ts timestamptz DEFAULT now()
);
CREATE INDEX access_log_client_gist ON access_log USING gist (client inet_ops);
SELECT * FROM access_log WHERE client << '10.0.0.0/8'::cidr;
```

Source : postgresql.org/docs/17/datatype-net-types.html.

## Range and Multirange Types

Built-in ranges : `int4range`, `int8range`, `numrange`, `tsrange`, `tstzrange`, `daterange`. Multirange (v14+) : `int4multirange`, `tstzmultirange`, etc.

```sql
-- A reservation that occupies a time window
CREATE TABLE reservations (
  id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  room int NOT NULL,
  during tstzrange NOT NULL,
  -- Exclusion constraint : no two reservations of the same room overlap
  EXCLUDE USING gist (room WITH =, during WITH &&)
);

INSERT INTO reservations (room, during) VALUES
  (1, '[2026-05-19 10:00, 2026-05-19 11:00)');

-- Query : reservations overlapping a window
SELECT * FROM reservations
WHERE during && '[2026-05-19 10:30, 2026-05-19 11:30)'::tstzrange;
```

Range operators : `@>` (contains), `<@` (is contained by), `&&` (overlaps), `<<` (strictly left of), `>>` (strictly right of), `-|-` (adjacent). Construct with `[lower, upper)` literal syntax (square = inclusive, round = exclusive). For exclusion constraints USING gist, install `btree_gist` extension if combining with `=`.

Source : postgresql.org/docs/17/rangetypes.html.

## Array Types

Every non-array type has an array variant : `int[]`, `text[]`, `jsonb[]`, etc. Multi-dimensional arrays exist but rarely improve clarity over a join.

```sql
CREATE TABLE posts (
  id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  tags text[] DEFAULT '{}'
);
INSERT INTO posts (tags) VALUES (ARRAY['postgres', 'mvcc']);

-- Membership
SELECT * FROM posts WHERE 'postgres' = ANY (tags);

-- Index with GIN for overlap / contains
CREATE INDEX posts_tags_gin ON posts USING gin (tags);
SELECT * FROM posts WHERE tags && ARRAY['postgres']::text[];   -- overlaps
SELECT * FROM posts WHERE tags @> ARRAY['postgres', 'mvcc'];   -- contains
```

When the array has unbounded length and is heavily queried, a join table is usually clearer and more flexible. Reach for arrays for fixed-small lists (tags, role names).

Source : postgresql.org/docs/17/arrays.html.

## Composite Types

User-defined struct types built via `CREATE TYPE name AS (field type, ...)`. Useful for returning multi-field records from functions and for column types that group fields cleanly.

```sql
CREATE TYPE address AS (
  street text,
  city   text,
  zip    text
);

CREATE TABLE customers (
  id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  home address,
  work address
);

INSERT INTO customers (home, work) VALUES
  (ROW('Hoofdstraat 1', 'Amsterdam', '1011AA'),
   ROW('Bedrijfslaan 9', 'Utrecht',   '3500AA'));

SELECT id, (home).city, (work).zip FROM customers;
```

Source : postgresql.org/docs/17/rowtypes.html.

## Enum Types

`CREATE TYPE name AS ENUM ('a', 'b', 'c')`. Enum values have a fixed order matching declaration order. Storage is compact (4 bytes per value) and indexable.

```sql
CREATE TYPE order_status AS ENUM ('pending', 'paid', 'shipped', 'cancelled');

CREATE TABLE orders (
  id int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  status order_status NOT NULL DEFAULT 'pending'
);
```

CRITICAL : adding an enum value uses `ALTER TYPE ... ADD VALUE`, which since v12 commits immediately and cannot be rolled back inside a transaction. Renaming a value is supported with `RENAME VALUE`. Removing a value requires recreating the type (expensive on production).

```sql
ALTER TYPE order_status ADD VALUE IF NOT EXISTS 'refunded';
```

When values change frequently OR need referential metadata (description, sort order), use a lookup TABLE with a foreign key instead of an enum.

Source : postgresql.org/docs/17/datatype-enum.html, postgresql.org/docs/17/sql-altertype.html.

## Domain Types

A domain is a named type with optional NOT NULL, DEFAULT, and CHECK constraints layered on top of a base type. Use domains to centralize validation rules.

```sql
CREATE DOMAIN email AS text
  CHECK (VALUE ~ '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$');

CREATE DOMAIN positive_int AS integer
  CHECK (VALUE > 0);

CREATE TABLE customers (
  id positive_int GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  contact email NOT NULL
);

-- Violations raise SQLSTATE 23514 check_violation
INSERT INTO customers (contact) VALUES ('not-an-email');
-- ERROR : value for domain email violates check constraint "email_check"
```

Domain constraints are enforced at write time. Domains compose : a column declared as a domain can also have its own NOT NULL / DEFAULT. Limitations : domains over arrays exist but interact awkwardly with composite types ; foreign keys must reference the base type, not the domain.

Source : postgresql.org/docs/17/domains.html, postgresql.org/docs/17/sql-createdomain.html.

## Type Casting

Three forms :

```sql
-- 1. Explicit cast operator (PostgreSQL extension, common)
SELECT '42'::int;

-- 2. SQL standard CAST()
SELECT CAST('42' AS int);

-- 3. Function-call form for types whose name is a single identifier
SELECT int4('42');
```

Implicit casts have been LIMITED since v8.3 : `WHERE int_col = 'string'` no longer auto-casts the string. Mixed-type comparisons must cast explicitly.

```sql
-- WORKS : both sides int
SELECT * FROM t WHERE int_col = 42;

-- WORKS : explicit cast
SELECT * FROM t WHERE int_col = '42'::int;

-- FAILS : SQLSTATE 42883 operator does not exist : integer = text
SELECT * FROM t WHERE int_col = '42'::text;
```

A common production bug : `WHERE varchar_col = 123` causes a cast on every row, which can defeat an index. Cast the parameter, not the column. See `references/anti-patterns.md` of `postgres-core-indexing-strategy`.

Source : postgresql.org/docs/17/typeconv.html, postgresql.org/docs/17/sql-expressions.html.

## Picking The Right Type : Decision Summary

```
Need an exact identity ?              → bigint GENERATED ALWAYS AS IDENTITY
Need a global identity ?              → uuid (gen_random_uuid())
Need a string ?                       → text  (varchar(n) only when length cap is a business rule)
Need a date/time ?                    → timestamptz
Need exact decimal ?                  → numeric(p, s)
Need a fixed list of values ?         → enum (ALTER TYPE ADD VALUE is non-rollbackable)
                                        OR a lookup table (more flexible)
Need a time/numeric window ?          → tstzrange / int4range + EXCLUDE constraint
Need a small fixed-length list ?      → text[]  +  GIN index
Need a structured composite record ?  → composite type (CREATE TYPE ... AS)
Need to enforce a validation rule ?   → domain (CREATE DOMAIN ... CHECK)
Need an IP / MAC address ?            → inet / cidr / macaddr
Need a schema-flexible document ?     → jsonb  +  GIN (jsonb_path_ops) for @> queries
```

Source : postgresql.org/docs/17/datatype.html (full type overview).
