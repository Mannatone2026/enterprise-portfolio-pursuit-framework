# postgres-syntax-dml-ddl : Methods Reference

## CREATE TABLE : Full Grammar

```sql
CREATE [ [ GLOBAL | LOCAL ] { TEMPORARY | TEMP } | UNLOGGED ] TABLE [ IF NOT EXISTS ] table_name (
    column_or_constraint [, ...]
)
[ INHERITS ( parent_table [, ...] ) ]
[ PARTITION BY { RANGE | LIST | HASH } ( column_or_expr [, ...] ) ]
[ USING access_method ]
[ WITH ( storage_param = value [, ...] ) | WITHOUT OIDS ]
[ ON COMMIT { PRESERVE ROWS | DELETE ROWS | DROP } ]
[ TABLESPACE tablespace_name ]
```

`column_or_constraint` is one of :

```sql
-- Column definition :
column_name data_type
    [ COMPRESSION { pglz | lz4 } ]                              -- v14+ , lz4 needs build flag
    [ COLLATE collation ]
    [ STORAGE { PLAIN | EXTERNAL | EXTENDED | MAIN | DEFAULT } ]
    [ column_constraint ... ]

-- Table-level constraint :
[ CONSTRAINT constraint_name ]
{ CHECK ( expression ) [ NO INHERIT ]
  | UNIQUE [ NULLS [ NOT ] DISTINCT ] ( column_name [, ...] ) index_parameters
  | PRIMARY KEY ( column_name [, ...] ) index_parameters
  | EXCLUDE [ USING method ] ( exclude_element WITH operator [, ...] ) index_parameters [ WHERE ( predicate ) ]
  | FOREIGN KEY ( column_name [, ...] ) REFERENCES reftable [ ( refcolumn [, ...] ) ]
        [ MATCH { FULL | PARTIAL | SIMPLE } ]
        [ ON DELETE referential_action ]
        [ ON UPDATE referential_action ]
}
[ DEFERRABLE | NOT DEFERRABLE ] [ INITIALLY { DEFERRED | IMMEDIATE } ]

-- LIKE clause (in place of a column) :
LIKE source_table [ { INCLUDING | EXCLUDING } { ALL | COMMENTS | COMPRESSION
                      | CONSTRAINTS | DEFAULTS | GENERATED | IDENTITY
                      | INDEXES | STATISTICS | STORAGE } ... ]
```

`column_constraint` is one of :

```sql
[ CONSTRAINT name ]
{ NOT NULL
  | NULL
  | CHECK ( expression ) [ NO INHERIT ]
  | DEFAULT default_expr
  | GENERATED ALWAYS AS ( generation_expr ) STORED
  | GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY [ ( sequence_option [ ... ] ) ]
  | UNIQUE [ NULLS [ NOT ] DISTINCT ] index_parameters
  | PRIMARY KEY index_parameters
  | REFERENCES reftable [ ( refcolumn ) ]
        [ MATCH FULL | MATCH PARTIAL | MATCH SIMPLE ]
        [ ON DELETE referential_action ]
        [ ON UPDATE referential_action ]
}
[ DEFERRABLE | NOT DEFERRABLE ] [ INITIALLY { DEFERRED | IMMEDIATE } ]
```

`referential_action` : `NO ACTION` (default), `RESTRICT`, `CASCADE`, `SET NULL [ ( column_name [, ...] ) ]`, `SET DEFAULT [ ( column_name [, ...] ) ]`. v15 added the optional column list on `SET NULL` / `SET DEFAULT`.

Source : postgresql.org/docs/17/sql-createtable.html.

## IDENTITY Columns : Sequence Options

```sql
GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY [ (
    INCREMENT [ BY ] n
    | MINVALUE m | NO MINVALUE
    | MAXVALUE m | NO MAXVALUE
    | START [ WITH ] s
    | CACHE n
    | [ NO ] CYCLE
    | SEQUENCE NAME explicit_sequence_name
) ]
```

| Mode | User INSERT supplies a value? |
|---|---|
| `GENERATED ALWAYS AS IDENTITY` | Rejected with SQLSTATE `428C9` unless `OVERRIDING SYSTEM VALUE` is used. |
| `GENERATED BY DEFAULT AS IDENTITY` | Accepted (user value wins) ; sequence used only when value omitted. |

Identity columns own their sequence , `DROP TABLE` drops it ; `ALTER TABLE DROP COLUMN` drops it. No separate GRANT USAGE is required on the implicit sequence (unlike `serial`). Source : postgresql.org/docs/17/sql-createtable.html.

## SERIAL is Deprecated : Migration Recipe

```sql
-- Identify SERIAL columns :
SELECT a.attname, pg_get_serial_sequence(c.oid::regclass::text, a.attname)
FROM pg_attribute a
JOIN pg_class c ON c.oid = a.attrelid
WHERE pg_get_serial_sequence(c.oid::regclass::text, a.attname) IS NOT NULL;

-- Convert serial -> GENERATED BY DEFAULT AS IDENTITY (v15+) :
ALTER TABLE t
    ALTER COLUMN id DROP DEFAULT,                                    -- drop nextval(seq)
    ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY (RESTART WITH 1000);
-- Sequence becomes column-owned ; explicit nextval() calls keep working.
```

`serial` / `bigserial` / `smallserial` are pseudo-types that expand to `integer/bigint/smallint NOT NULL DEFAULT nextval('seq')` plus a separate sequence object owned by the column. They cannot be made `GENERATED ALWAYS`. Source : postgresql.org/docs/17/datatype-numeric.html#DATATYPE-SERIAL.

## GENERATED ALWAYS AS (expr) STORED

```sql
column_name data_type GENERATED ALWAYS AS ( expression ) STORED
```

Rules :
- v15-v17 : `STORED` is the only mode. `VIRTUAL` ships in v18.
- `expression` MUST be immutable (no `now()`, no subqueries, no calls to volatile functions).
- May reference other columns in the **same row** but NOT other generated columns.
- The column is recomputed on every UPDATE that changes any referenced column.
- Behaves like a regular column for indexing : `CREATE INDEX ON t (generated_col)` works.

Source : postgresql.org/docs/17/ddl-generated-columns.html.

## INSERT : Full Grammar

```sql
[ WITH [ RECURSIVE ] with_query [, ...] ]
INSERT INTO table_name [ AS alias ] [ ( column_name [, ...] ) ]
    [ OVERRIDING { SYSTEM | USER } VALUE ]
    { DEFAULT VALUES
      | VALUES ( { expression | DEFAULT } [, ...] ) [, ( ... ) ...]
      | query
    }
    [ ON CONFLICT [ conflict_target ] conflict_action ]
    [ RETURNING { * | output_expression [ [ AS ] output_name ] } [, ...] ]
```

`OVERRIDING SYSTEM VALUE` : required to supply a user value to a `GENERATED ALWAYS AS IDENTITY` column.
`OVERRIDING USER VALUE` : on `GENERATED BY DEFAULT AS IDENTITY`, ignores the supplied value and uses the sequence.
`DEFAULT` keyword in `VALUES` : use the column's DEFAULT or IDENTITY value for that one cell.

`ON CONFLICT` covered in `postgres-syntax-merge-upsert`. Source : postgresql.org/docs/17/sql-insert.html.

## UPDATE : Full Grammar

```sql
[ WITH [ RECURSIVE ] with_query [, ...] ]
UPDATE [ ONLY ] table_name [ * ] [ [ AS ] alias ]
    SET { column_name = { expression | DEFAULT }
          | ( column_name [, ...] ) = [ ROW ] ( { expression | DEFAULT } [, ...] )
          | ( column_name [, ...] ) = ( sub-SELECT )
        } [, ...]
    [ FROM from_item [, ...] ]
    [ WHERE condition | WHERE CURRENT OF cursor_name ]
    [ RETURNING { * | output_expression [ [ AS ] output_name ] } [, ...] ]
```

Notes :
- `UPDATE ... FROM` is a join ; the planner uses it like an inner join, so unmatched rows of the target are not updated.
- Multiple matches on the join key cause **non-deterministic** picks (the first row wins). Filter on a unique key.
- `WHERE CURRENT OF cursor_name` updates the row the named cursor is positioned on (used inside pl/pgSQL FOR loops).

Source : postgresql.org/docs/17/sql-update.html.

## DELETE : Full Grammar

```sql
[ WITH [ RECURSIVE ] with_query [, ...] ]
DELETE FROM [ ONLY ] table_name [ * ] [ [ AS ] alias ]
    [ USING from_item [, ...] ]
    [ WHERE condition | WHERE CURRENT OF cursor_name ]
    [ RETURNING { * | output_expression [ [ AS ] output_name ] } [, ...] ]
```

Notes :
- `USING` is the DELETE equivalent of `UPDATE ... FROM`.
- Returns a command tag `DELETE <rowcount>`.
- TRUNCATE is faster for full-table empty operations (see below).

Source : postgresql.org/docs/17/sql-delete.html.

## TRUNCATE

```sql
TRUNCATE [ TABLE ] [ ONLY ] name [ * ] [, ... ]
    [ RESTART IDENTITY | CONTINUE IDENTITY ]
    [ CASCADE | RESTRICT ]
```

| Option | Effect |
|---|---|
| `RESTART IDENTITY` | Reset all sequences owned by IDENTITY columns on the truncated tables. |
| `CONTINUE IDENTITY` (default) | Sequences keep their current value. |
| `CASCADE` | Also truncate every table that has a FK reference to a listed table (recursive). |
| `RESTRICT` (default) | Refuse if other tables FK-reference a listed table. |
| `ONLY t` | Truncate only `t`, not its partitions / inheritance children. |
| `t` (no ONLY) | Truncate the named table and all descendant partitions / children. |

Behavior :
- Takes `ACCESS EXCLUSIVE` lock on every named table. Blocks all readers and writers.
- Fires `ON TRUNCATE` triggers ; does **not** fire `ON DELETE` triggers.
- Reclaims disk immediately (drops + recreates the underlying relfilenode).
- Fully transactional : `BEGIN; TRUNCATE t; ROLLBACK;` leaves rows intact.

Source : postgresql.org/docs/17/sql-truncate.html.

## ALTER TABLE : Subcommand Summary

| Subcommand | Lock level | Notes |
|---|---|---|
| `ADD COLUMN col t` (no DEFAULT) | ACCESS EXCLUSIVE | Metadata-only ; existing rows materialize NULL. |
| `ADD COLUMN col t DEFAULT non_volatile` | ACCESS EXCLUSIVE | v11+ : no rewrite ; default stored in `pg_attribute`. |
| `ADD COLUMN col t DEFAULT volatile_fn()` | ACCESS EXCLUSIVE | Full table rewrite. |
| `DROP COLUMN col` | ACCESS EXCLUSIVE | Metadata-only ; space reclaimed lazily. |
| `ALTER COLUMN col TYPE new_type` | ACCESS EXCLUSIVE | Rewrite unless binary-coercible without USING. |
| `ALTER COLUMN col SET DEFAULT expr` / `DROP DEFAULT` | ACCESS EXCLUSIVE | Metadata-only. |
| `ALTER COLUMN col SET NOT NULL` | ACCESS EXCLUSIVE | Full table scan unless preceded by `CHECK (col IS NOT NULL) NOT VALID` + VALIDATE. |
| `ALTER COLUMN col DROP NOT NULL` | ACCESS EXCLUSIVE | Metadata-only. |
| `ALTER COLUMN col SET STATISTICS n` | SHARE UPDATE EXCLUSIVE | No rewrite. |
| `ALTER COLUMN col SET STORAGE m` | ACCESS EXCLUSIVE | New rows only. |
| `ADD CONSTRAINT c CHECK (...) [NOT VALID]` | ACCESS EXCLUSIVE | NOT VALID skips the scan. |
| `ADD CONSTRAINT fk FOREIGN KEY ... [NOT VALID]` | SHARE ROW EXCLUSIVE | NOT VALID skips the scan. |
| `VALIDATE CONSTRAINT c` | SHARE UPDATE EXCLUSIVE | Validates a NOT VALID constraint. |
| `DROP CONSTRAINT c` | ACCESS EXCLUSIVE | Metadata-only. |
| `RENAME COLUMN / CONSTRAINT / TO` | ACCESS EXCLUSIVE | Metadata-only. |
| `SET SCHEMA s` | ACCESS EXCLUSIVE | Metadata-only. |
| `OWNER TO r` | ACCESS EXCLUSIVE | Metadata-only. |
| `ATTACH PARTITION` | SHARE UPDATE EXCLUSIVE on parent | v12+ reduced lock. |
| `DETACH PARTITION p` | SHARE EXCLUSIVE | Default ; takes parent lock. |
| `DETACH PARTITION p CONCURRENTLY` | SHARE UPDATE EXCLUSIVE | v14+ ; cannot be inside a transaction. |
| `ENABLE / DISABLE TRIGGER / RULE / ROW LEVEL SECURITY` | ACCESS EXCLUSIVE | Metadata. |
| `SET ACCESS METHOD m` | ACCESS EXCLUSIVE | v15+ ; full rewrite. |
| `SET LOGGED / UNLOGGED` | ACCESS EXCLUSIVE | Full table rewrite. |
| `CLUSTER ON idx` / `SET WITHOUT CLUSTER` | ACCESS EXCLUSIVE | Metadata-only ; future `CLUSTER` uses idx. |

Multiple subcommands in one statement share the lock acquisition ; the **strictest** required lock is held for the whole statement. Source : postgresql.org/docs/17/sql-altertable.html.

## Transactional DDL : Exceptions

Statements that CANNOT run inside a transaction block (SQLSTATE `25001` / `0A000`) :

- `CREATE INDEX CONCURRENTLY` / `REINDEX CONCURRENTLY` / `DROP INDEX CONCURRENTLY`
- `DETACH PARTITION ... CONCURRENTLY` (v14+)
- `ALTER TYPE ... ADD VALUE` (enum value add ; v12+ allows if value is new in same transaction)
- `ALTER SYSTEM SET ...` / `ALTER SYSTEM RESET ...`
- `VACUUM` / `VACUUM FULL` / `ANALYZE` ; `REINDEX` (non-concurrent forms inside a function may also fail)
- `CREATE DATABASE` / `DROP DATABASE`
- `CREATE TABLESPACE` / `DROP TABLESPACE`
- `CLUSTER` (without arguments , whole database)

Everything else (`CREATE/ALTER/DROP TABLE`, `CREATE INDEX` non-concurrent, `GRANT`/`REVOKE`, `CREATE/ALTER/DROP ROLE`, `CREATE/ALTER/DROP TYPE` for non-enum-add) is transactional. Source : postgresql.org/docs/17/sql-createindex.html, postgresql.org/docs/17/sql-altertable.html.

## RETURNING : Output Forms

```sql
RETURNING *
RETURNING col1, col2, expr AS name
RETURNING * EXCEPT (col)         -- v17+ (postponed feature ; check release notes)
```

RETURNING works on INSERT, UPDATE, DELETE, and (v17+) MERGE. The expressions execute after defaults, BEFORE triggers, and column generation have applied , so generated columns and IDENTITY values are visible. Source : postgresql.org/docs/17/sql-insert.html, postgresql.org/docs/17/sql-update.html, postgresql.org/docs/17/sql-delete.html.
